# SKF Distributor Copilot 业务背景（Business Context）

## 业务目标

构建 AI 驱动的经销商 Copilot（SKF Distributor Growth Assistant, DGA），帮助 SKF 经销商：

- 选择正确的 SKF 产品（技术选型）
- 查询库存可用性
- 生成报价单
- 推荐互补产品（交叉销售）
- 回答技术问题
- 处理经销商支持请求

Copilot 相当于以下角色的组合：技术工程师、库存协调员、定价分析师、销售助理、交叉销售顾问、客服专员。

## 流程改进

**现状**：经销商 → 致电 SKF → 等工程师 → 等定价团队 → 等库存团队 → 客户拿到报价（多次等待，周期长）

**目标**：经销商 → Distributor Copilot → 技术推荐 → 库存确认 → 定价 → 交叉销售 → 报价单（一次对话完成）

## 能力与业务价值对应

| Capability | Business Outcome |
|------------|------------------|
| Technical Copilot | Faster dealer response（更快响应经销商） |
| Inventory Copilot | Improved order conversion（提升订单转化） |
| Pricing Copilot | Reduced manual effort（减少人工报价） |
| Cross Sell Engine | Higher revenue per order（提升单均收入） |
| Quote Generation | Faster sales cycle（缩短销售周期） |
| Knowledge Assistant | Reduced dependency on SKF experts（降低对专家依赖） |

## 经销商分级（Distributor Segments）

- **Class A**（Top 20）：年采购额 > ¥500 万，折扣最高（轴承类 37%）
- **Class B**（Mid 30）：年采购额 ¥200 万 - ¥500 万（轴承类 29%）
- **Class C**（Bottom 10）：年采购额 < ¥200 万（轴承类 20%）

## 仓库网络

- 上海 DC（主仓，每周补货）
- 大连 DC（每两周补货）
- 济南 DC（每两周补货）

## POC 架构（文档建议）

- **Layer 1 知识层**：静态信息存向量库（产品目录、工程指南、应用指南、竞品对照、FAQ）
- **Layer 2 交易数据层**：动态信息存结构化 JSON 或 SQL（库存、价格、经销商等级、报价数据）
- **Layer 3 业务规则引擎**：所有业务规则清单（定价规则、交叉销售逻辑、置信度分级）

## AI 置信度策略

- 高置信度（>80%）：直接给出完整答案
- 中置信度（60-80%）：给出答案并附免责说明，提供人工升级入口
- 低置信度（<60%）：自动升级到人工工程师

## POC 验收指标

| 指标 | 目标 |
|------|------|

| 交叉销售接受率 | >70% |
